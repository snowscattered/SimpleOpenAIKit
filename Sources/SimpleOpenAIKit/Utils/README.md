# Utils

Small shared helpers that sit between the session and the network layer.

## Contents

| Path | Meaning |
| --- | --- |
| `BaseUtiles.swift` | `decodeNetworkData` and the sync/async `retry` loops |
| `NoStreamUtils.swift` | `syncResponse` / `asyncResponse`: one body, decoded or returned raw |
| `StreamUtils.swift` | `syncStreamResponse` / `asyncStreamResponse`: SSE events mapped to values |
| `ToolProtocol.swift` | One tool as a type, plus `ChatTool` / `ResponseTool` / `MessageTool` bridges |

## Rules

- `retry` backs off exponentially from `delay`, capped at 8 seconds, and stops when `maxRetries` is
  spent or `shouldRetry` rejects the error. Retries cover establishing the response, not replaying
  chunks already delivered.
- `Data` as the result type short-circuits decoding, which is how binary downloads (speech, video) work.
- `StreamUtils.EventConversion` is the SSE-to-value policy: empty data and Anthropic `ping` are
  skipped, `[DONE]` ends the stream, everything else decodes as the target type.
- A `ToolProtocol` type is the single source of truth for a tool: its `Arguments` carries the JSON
  schema generated by the macros, and `call(_ data:)` is the entry point for tool calls arriving from
  a response or stream. Tool bodies run `@concurrent` so a stream keeps draining while a tool executes.
